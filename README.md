## How to get a port

1. **Search first.** There is a good chance someone already asked.
   [Search open requests](https://github.com/Cerberus-9dev/request-minecraft-mod-ports/issues?q=is%3Aissue+is%3Aopen).
2. **Check the license.** If the mod is All Rights Reserved and the author hasn't said ports are okay,
   attach proof of permission in the form. I won't redistribute someone's code against their license.
3. **Fill in the form.** It asks for the target version, loader, license, and any blockers. One mod per request.
4. **Wait.** No ETAs. Requests are triaged in vote order, roughly daily-weekly.

## What I'm likely to pick up

- Open source, or the author has clearly permitted ports.
- Mods people actually use — votes and "this blocks my update" context help.
- Small, self-contained mods, or ones whose dependencies already exist on the target version.
- Jumps of one or two versions rather than a rewrite across five.

## What I'll decline

- All Rights Reserved mods without permission. No exceptions, however popular the request.
- Mods whose only "source" is a decompiled/reuploaded jar.
- Requests that are really "update this modpack for me" — that's a different job.
- Anything needing a full rewrite of rendering/networking code for a version I don't play.

## Status labels

| Label | Meaning |
| --- | --- |
| `status: needs triage` | Not looked at yet. |
| `status: needs info` | I asked a question — reply and it moves again. |
| `status: accepted` | On my list, not started. |
| `status: in progress` | Actually being ported. |
| `status: blocked` | Waiting on a dependency, the author, or an upstream fix. |
| `status: done` | Ported — the request is closed and links to the release. |
| `status: declined` | Won't happen; the reason is in the thread. |

## Rules

- One mod per request, one request per mod and target version.
- Be civil. Rudeness or DMing me about a request gets it closed.
- No paying for priority, and no offering to pay — ports are free.
